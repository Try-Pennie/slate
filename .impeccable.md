# Impeccable — Slate design context

## Design Context

### Source of truth
Slate's UI is built on the **exported Pennie Design System**, on disk at
`~/Documents/Pennie Branding/Pennie Design System/`. It is code, not just specs:
- `colors_and_type.css` — all tokens as CSS variables (`--pennie-*`, semantic
  `--bg/--fg/--accent/--border/--focus-ring`, radii, shadows, `--space-*`) plus base
  component classes (`.pn-btn`, `.pn-card`, `.pn-h1`…`.pn-eyebrow`). Port these into Slate
  and wire them into Tailwind v4 `@theme`. Use variables, never raw hex.
- `assets/` — logo SVGs (charcoal/cream/mark/lg), `currentColor` UI + product icons,
  `people/` photography. `fonts/` — PP Mori OTFs (200/400/600).
- `preview/*.html` — one rendered card per token/component; consult when unsure.
- `README.md` + `SKILL.md` — voice and usage rules.

This export **supersedes** the older markdown `pennie-brand.skill` wherever they conflict
(font weights, button text color, 4px radius). When in doubt, the shipped CSS wins.

### Users
Two audiences, both fully branded:
1. **Borrowers** (consumer) — book a call via the embeddable **Booker**/`widget.js` from
   Pennie landing pages. Often financially stressed; want simplicity, speed, reassurance.
   This surface gets pixel-perfect, consumer-grade polish.
2. **Pennie staff** (internal) — agents/managers/admins using `admin`, `me`, `login` to
   manage the round-robin booking pool. On-brand and consistent, task-efficient.
   These pages support **both light and dark** themes.

**Booker treatment:** clean, focused booking steps (nothing competing with the
calendar/time selection), with **one branded delight moment** on the confirmation/success
screen — an illustration + warm copy ("Nice. Sarah will call you Thursday at 2:00.").

### Brand Personality
Friendly, approachable financial **partner** — not a stiff bank, not a bro-y fintech.
Three words: **warm, confident, optimistic.** Pennie is a lending **marketplace** (not a
direct lender), and explicitly NOT the Pennsylvania health-insurance pennie.com.

Voice: short active sentences, plain English ("monthly payment," not "amortized
principal"), outcome-led, never fear-based or hype. Button copy is a verb phrase
("View my offers", "Continue") — never "Submit." Always disclose rates; never guarantee
("may / up to / based on eligibility").

### Aesthetic Direction
- **Beige/light-first**, per the system's 80/15/5 rule (beige or navy ≈80%, graphite text
  ≈15%, sky accent ≈5%). Navy is for occasional hero/stat/footer bands and rhythm — not a
  default canvas. The consumer Booker defaults to **beige/light** (the embed can override
  to dark via host config; both themes are maintained).
- **Color:** Beige `#F9F6F0` / White surfaces, Navy `#1D212F` bands, Graphite `#343434`
  text. **Sky `#82D0FF` is the only action color** (primary CTA = sky fill + graphite
  text). Yellow/mint/peach are illustration/sticky-note/testimonial accents — **never
  CTAs**. One colored fill per screen. No hard black (`#000`); muted rose `#C43D3D` for
  errors. Reference: trypennie.com. Anti-reference: cold fintech dashboards, crypto hype.
- **Type:** PP Mori only — **200 Extralight / 400 Regular / 600 SemiBold** (no Medium; 700
  aliases to 600; `font-synthesis: none`). Body = Regular 400; headings = SemiBold 600
  (the signature weight — never 700/800). Tabular numerals on rates/payments/stats.
  Helvetica Now Display is NOT used.
- **Shape:** Buttons **16px rounded** (per shipped CSS `.pn-btn--big`, not pills). Cards
  16px. Large surfaces/bands 24px. Chips/tags 4px. Pills (999px) reserved for badges.
  Soft low-contrast shadows from the `--shadow-*` tokens — never a hard black drop shadow.

### Accessibility
**WCAG 2.1 AA + extra care.** 4.5:1 text / 3:1 UI contrast; visible focus (the sky
`--focus-ring` glow, already in the system); full keyboard nav; honor
`prefers-reduced-motion`; screen-reader labels on all controls. Color is never the sole
signal (pair with text/icon). Generous touch targets (44px+). Verify sky-on-beige and
graphite-on-sky pairings actually pass — sky is light, so CTA label contrast needs checking.

### Design Principles
1. **Port, don't reinvent.** Compose from `colors_and_type.css` tokens and `.pn-*`
   classes first; only add styles when nothing fits. The design system is the source of
   truth — shipped CSS beats the README narrative on conflicts.
2. **Beige-first rhythm.** Lead with beige/white; use navy as deliberate accent bands.
   Don't stack three same-color sections; one CTA per band.
3. **Sky means action.** Sky is the only interactive fill. Warm accents are decoration.
4. **Plain, optimistic, honest copy.** Verb-phrase buttons, outcome-led headlines, always
   disclose, never guarantee.
   - **A switch's help text says only what its current state means** (on, or off), in as
     few words as carry the facts, never both states at once and never an "On:"/"Off:"
     label. Why, Dan, 2026-10-26, on /admin/alerts: "I think in general this page is too
     noisy. We should probably show on OR off based on the current state and the wording
     probably can be less 'wordy'." `AlertSwitch` (`src/components/admin/AlertSwitch.tsx`)
     follows the box live, before saving.
5. **Accessible by construction.** AA+ contrast, visible focus, reduced-motion, SR labels,
   color never the sole signal — built in, not bolted on.
